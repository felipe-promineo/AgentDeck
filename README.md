# Agent Hub

(Called AgentDeck before. The repository, the npm package name and the settings folder `~/Library/Application Support/agentdeck` keep the old name.)

A desktop app for running and managing Claude Code agents. You can change anything in it.

## Run it

```bash
npm install
npm start
```

You need Node.js, Git, and Claude Code installed and logged in (`claude` in a terminal, then `/login`). Agent Hub runs on macOS and Windows.

### As a clickable app

```bash
npm run make-app
```

Run this in the stable copy (see below).

- **macOS:** it builds `~/Applications/Agent Hub.app` with the Agent Hub icon and puts a link to it on your Desktop.
- **Windows:** it creates "Agent Hub" shortcuts on the Desktop and in the Start menu, with the Agent Hub icon.

Both run the code in that folder directly, so after an update you only quit and reopen Agent Hub. Since Electron 42 (the app uses Electron 45), `npm install` no longer downloads Electron itself; `npm start` does on its first run, and `npm run make-app`, promote and the self-update do it when it is missing (`node node_modules/electron/install.js`). Run `npm run make-app` again only after `npm install` updates Electron, or after you change the icon (`build/icon.html`, then `npm run icon`, which writes `icon.png` and the Windows `icon.ico`).

### On Windows

- **Setting up the two copies:** clone the repository, then in it run `git checkout dev`, `git worktree add ../AgentDeck-stable master`, and `npm install` in both folders. Then run `npm run make-app` in `AgentDeck-stable`.
- **Shortcuts:** use Ctrl where this README says ⌘.
- **Finding Claude Code:** Agent Hub looks for `claude` in the native installer's folder (`%USERPROFILE%\.local\bin`), the npm folder (`%APPDATA%\npm`), wherever `where claude` finds it, and the Claude desktop app's own copy, and uses the newest. If it picks the wrong one, set `claudePath` in Settings.

## Two copies: stable and dev

The app you use every day and the code you change live in two separate folders, so a broken change never breaks the app you are working in. Both folders share one git history (they are git worktrees).

| Folder | Branch | Used for |
| --- | --- | --- |
| `~/Repositories/AgentDeck-stable` | `master` | Agent Hub.app runs this code. Don't edit it directly. |
| `~/Repositories/AgentDeck` | `dev` | Make and commit changes here. Test them with `npm start`, which opens a second window that runs the dev code. |

The version next to the title tells the two apart. The stable copy shows the version from `package.json` (`v0.3.0`). The dev copy shows master's major and minor version, with the number of commits it is ahead of master as the patch number, in amber: `v0.3.4 dev`.

When a change works, move it to the stable copy from the dev folder:

```bash
npm run promote
```

This moves `master` forward to `dev`, installs packages in the stable copy if they changed, and rebuilds Agent Hub.app if the icon or Electron changed. Then quit and reopen Agent Hub. To also set a version number and tag it, and to upload everything to GitHub:

```bash
npm run promote -- 0.3.0 --push
```

Click the version next to the title to see the changelog: every release, newest first, with the changes since the release before it and the date, and "Your version" next to the one you run. It is made from git (the version tags and the commit messages between them), so it needs no writing by hand; in the dev copy, commits since the last release come first as "Not released yet".

The stable copy also updates itself from GitHub. 3 seconds after it opens, every time its window gets the focus, and every 30 minutes, it checks whether `master` on GitHub is ahead of it (Settings → Updates → Check for updates checks right away). When it is, you are on the Hub (not in an agent's chat) and no agent is running (working, asking you something, or with work in the background, or just sent a message it has not started on yet, as when sending takes you back to the Hub), a card asks you to update; while agents run, the card waits and comes as soon as the last one is done. It has one button, Update and restart, and Esc or a click outside does not close it. After the restart the Hub is as you left it: agents you have not checked yet still wait for you. An amber "v0.6.6 available" button also appears next to the version; point at it to see what's new. When the new version needs other packages, the app installs them after it quits (and rebuilds the clickable app if Electron changed), then opens again. The button is only offered when the stable copy is on `master` without commits of its own; if the folder has uncommitted changes, the card says the update failed and why, and only then can you close it. The dev copy never checks.

To go back to an earlier version, check out its tag in the stable copy (`git -C ~/Repositories/AgentDeck-stable checkout v0.2.0`), then reopen the app.

## What it does

- **New agent.** Agents start only from the message box at the bottom of the Hub (⌘N puts the cursor there). The buttons under the message box set the folder (it starts with the folder of the agent you started last; click it for recent folders or Choose folder…), the group, the permissions and the model. Press ↩ to start the agent: the box morphs into its tile.
- **Voice input.** The microphone button next to Send (or ⌘⇧Space; Ctrl+Shift+Space on Windows) listens, and what you say appears in the message box while you speak, where the cursor was. The button turns red, and a ring around it grows with how loud you speak. Click it again (or press the keys again) to stop; Enter stops and sends once the last words are in; Esc stops and puts back the text the box had before; typing stops it and keeps the text. The system's own speech recognition turns your voice into text, so nothing is downloaded: on macOS Apple's (on the Mac itself when the language allows it), on Windows the recognizer that comes with Windows. Settings → App → Voice language picks the language; empty is the system's. On macOS the first use asks you to allow **Agent Hub Voice** to use speech recognition and the microphone. It asks for itself, not for Agent Hub, because Agent Hub gets a new signature each time it is rebuilt and macOS would forget what you allowed. The helper is `src/voice/voice-mac`, built from `voice-mac.swift` with `scripts/build-voice-mac.sh` and kept in the repository, so nobody needs Xcode; on Windows it is `src/voice/voice-win.ps1`.
- **Hub.** The main screen (⌘0, or ← Hub in an agent) shows every running agent as a tile with a tank of liquid. The color shows the state: blue starting, amber working (waves and bubbles, and the level rises with each step), orange needs your approval (the tile pulses), green done (a burst and a check mark when it finishes; until you open the agent, its tank keeps glowing and breathing, also after a restart), red error (the tile shakes). Each tile shows the task title, its status and how long the task took. Click a tile to open the agent: the agent's chat appears inside the tile, shrunk to fit, and in one smooth movement the tile and the chat inside it grow until the chat fills the window, while the Hub fades out underneath. Going back plays the same movement in reverse, and the tile lands in its place. After you send a message, the Hub opens and shows the agent's tile springing in (new agent) or hopping back to work (follow-up message); set `hubAfterSend` to `false` to stay in the chat instead.
- **GitHub links as cards.** A GitHub link in the chat becomes a card, like Jira tickets and Google files: the repository, the number (or commit, or file and lines), and from GitHub the title, the state (open, merged, closed, draft, passed, failed) and the lines it changes. Pull requests, issues, commits, workflow runs, releases, files and repositories get a card. The app asks GitHub with the GitHub CLI (`gh`, with your login, so private repositories work too); without it, only public repositories show their title.
- **Slack links as cards.** A link to a Slack message, thread reply or channel becomes a card with the workspace, what it links to (message, thread reply, direct message, channel), the link's own words if it has them, and when the message was sent. The app has no Slack login, so the card shows only what the link itself tells; the message text stays in Slack.
- **Progress of long tasks.** For tasks with several parts (animating several pieces, building a feature's model), agents write a one-line milestone each time they finish a part ("Milestone: 3 of 8 pieces animated"). Agent Hub shows the milestones, with the time since the task started, in a Progress panel at the top of the task in the chat, together with the agent's plan (its task list) and how much of it is done. The tile's step line shows the latest one. Milestones never notify you or play a sound; the panel folds away when the task is done.
- **Asset changes in words.** Under a task's code changes, the Changes card lists the Unity assets the task changed: prefabs first, then scenes, then materials, animations and the rest. Click one to see what changed in it, grouped by game object: game objects and components added or removed (scripts by their class name), values before → after with readable names ("RectTransform › Size delta: (230, 300) → (240, 300)"), renames, objects turned on or off, moves in the hierarchy, and the overrides of nested prefabs. Scripts and referenced assets are named from the project's .meta files, read once per project (the first asset takes a few seconds).
- **Keyboard in the Hub.** The selected group (where the message box points) always has one agent chosen, outlined on its tile. With the message box empty: ← → choose the previous or next agent in the group (Tab and ⇧Tab too, when no agent needs you; otherwise Tab opens the next agent to check), ↑ ↓ choose the previous or next group, and ↩ opens the next agent that needs you, or else the chosen one. Each group remembers its chosen agent.
- **Selecting several agents.** Shift+click or Ctrl+click (⌘+click on macOS) a tile to select it, or a panel's background to select all its agents. Shift and drag on the Hub draws a box, and every tile it touches is added to the selection. With agents selected, the Hub's message box sends your message to each of them. With 2 or more selected, **Close N selected** floats above the message box and removes them all from the Hub; when some of them are working, it asks once before it stops them. Their sessions stay in History. Esc unselects them.
- **Start from a Jira ticket.** Type a ticket key (`GAME-123`), or paste a ticket link, in the Hub's message box, with or without more words after it, and press ↩. The app reads the ticket (title, type, status and description) with the Atlassian CLI (`acli`, logged in to your Jira) and gives it to the new agent together with what you wrote. With only the key or link, the agent is told to do what the ticket asks. If the ticket can't be read, a note says why and the agent gets your message as it is. After each finished task of such an agent, a **Post this answer to GAME-123** button under the answer adds the answer to the ticket as a comment; nothing is posted until you click it.
- **Short titles.** A new agent is named with a summary of your message of at most 5 words, for example "Localization keys for shop offers". A quick, separate Claude Code call on Haiku writes it in about 2 seconds; until then the tile shows your message. The title is also used in History. Set `summarizeTitles` to `false` to keep your message as the title.
- **Hub groups.** Tiles are sorted into one panel per group and repository, titled "Group — Repository", so one group can have two panels when its agents work in two repositories. The repository is the nearest folder above the agent's folder that holds `.git` or `.svn` (for MyGame/Unity that is MyGame). A panel's tiles always stay on one row: they share its width and get smaller the more agents the group has (at most 240px wide each). The group button under the message box opens a panel: type a name and press ↩ to create a group, or pick one from the list. The list only shows groups that agents in the Hub use, with their agent count, so a group disappears from it when its last agent leaves; typing the exact name of such a group picks it again instead of creating a new one. Right-click a tile to move its agent to another group.
- **The Hub remembers its agents.** After a restart, or when an agent's process ends, its tile stays in the Hub as a green "Completed" tile with the time of its last task, the same as an agent that has just finished. Click it to open the session; your next message resumes it. Point at a tile and click × to remove it from the Hub. If the agent is still working, a card in the app asks first (the same as when you quit, or click Close agent or Remove group), since stopping it ends its task; ↩ stops it, Esc keeps it working. The session itself stays in History. The Hub also has a message box at the bottom with the same folder, group, permissions and model buttons as a new agent: type a task and press ↩, and the box morphs into the new agent's tile and flies to its place in the grid, while you stay in the Hub. Agents that were still working when you quit continue on their own when the app opens again: the app resumes their session and tells them to continue where they stopped. Quitting (or closing the window) while agents work asks first, in the app itself: a card lists the working agents and says they restart where they left off the next time you open the app (↩ quits, Esc keeps working).
- **History.** A drawer that slides in from the left (the History button in the Hub, the clock button at the top left, or ⌘\\; Esc closes it). It lists every session Claude Code has saved in `~/.claude/projects`. This includes sessions you ran in the terminal or in the Claude desktop app. Click one to read it, and type a message to continue it.
- **Categories and Groups.** A **Category** is a label you give sessions, for example one per domain. Click ＋ next to History to create one, drag a session onto it, or right-click a session and choose Move to category. Right-click a Category to rename it, move it up or down, or delete it (its sessions become uncategorized). A **Group** is one Category plus one folder, for example "Boards · MyGame/Unity"; the Hub shows one panel per Group. Categories are saved in `groups.json` next to `config.json`.
- **/ commands.** A message that starts with `/name` runs that skill or custom command in Claude Code, for example `/auditing:project-audit` or `/review`. While you type the name, a list above the message box shows the matching commands with their descriptions (your own, the project's, and your plugins'); ↑ ↓ move, Tab or ↩ takes one, Esc closes it. The group's shared notes and other text the app adds to a message wait for your next message, because a command must start the message.
- **Open Unity / Focus Unity.** A group whose folder is a Unity project (or holds one, like MyGame/Unity) has a Unity button in its title row, and so does an agent's message box. When that project's Unity Editor is open, **Focus Unity** brings its window to the front (the right one, also with several editors open); when it is not, **Open Unity** starts the editor version the project names in `ProjectSettings/ProjectVersion.txt`, from Unity Hub's install folder. The button checks every few seconds whether the editor is open.
- **Shared context in a Group.** A new agent in a Group always starts as a fork of the Group's most recently finished agent (`claude --resume <session> --fork-session`): it begins with a copy of that agent's conversation, so it knows what that agent read, did and decided, and the original stays untouched. Agents that are still working are skipped. The line under the message box shows which agent the next one continues from. The first agent of a Group starts fresh. Every fork carries the whole conversation, so contexts grow; Claude Code summarizes them when they get too long.
- **⚙ in the message box.** Permissions and model are almost always the defaults (bypass, latest Opus, medium effort), so their menus sit behind the ⚙ button; click it to show or hide them. When the settings differ from the defaults, the button names them, for example "⚙ Plan · Sonnet 5.5".
- **Model menu.** Under the message box, also for a new agent. It lists the same models, with the same descriptions, as the Claude desktop app, because the app asks your installed Claude Code for the list. You can also set the effort level and fast mode. A change applies to the agent on screen from its next message on.
- **Permission prompts.** When an agent wants to run a command or edit a file that your permission mode and rules don't already allow, an approval card appears in the chat, and the agent's dot turns orange ("Needs approval"). You can allow it once, deny it, or pick one of Claude Code's suggested rules (for example "Always allow Bash(npm start) in this project"). Claude Code saves that rule in the project's `.claude/settings.local.json`, the same file the terminal uses.
- **Chat.** Each of your messages starts a turn. While the agent works, one line shows what it is doing right now. When it finishes, the chat shows a **Changes** card that lists every file it changed, with a diff per file, followed by its final message. The steps in between (tool calls, thinking, notes) are collapsed into one line such as "12 steps · 34s · 57k tokens", which you can click to open.
- **Catching up when you come back.** While Agent Hub is on screen, the Hub animates live, also when another app has the focus. While it is minimized, the Hub's tiles keep the state you last saw. When you bring it back, the tiles that changed (finished, need you, stopped with an error) move to their new state one after another, each with its animation and sound, so you can see and hear what happened while you were away.
- **Order in the Hub.** A new agent's tile appears to the right of the others in its group, and a new group appears below the others. The order is kept after a restart.
- **Sorting tiles.** Drag a tile left or right within its group to change the order. While you hold it, the tile is lifted (bigger, tilted, swaying with your movement); the others slide aside to make room, and when you let go it falls into place. The order is kept after a restart.
- **Usage.** A small tab on the left edge of the Hub shows your session and week as two little meters; click it to open the usage card (click anywhere else or press Esc to close it). The card shows your plan's usage as Claude Code reports it with each agent's replies, and right when the app opens: then (and every 15 minutes after that, if no agent has reported it in the meantime) the app sends Haiku a one-word message, not saved as a session, only to get the numbers. That costs a very small amount of usage. It shows the current 5-hour session and this week, as a percentage with when each resets (green, amber from 70%, red from 90%). Below that, the tokens your agents used since Agent Hub opened. The last limits are remembered, so they show right after a restart (with how old they are).
- **Claude and Codex.** Agents run on Claude Code or on OpenAI's Codex CLI (Settings → Providers: turn each on or off, pick the one new agents start on, and Codex's default model and effort). Codex needs the Codex CLI installed and signed in (`brew install codex`, then `codex login`). With both on, the model menu lists Claude's models and Codex's (Auto, the newest Sol, Terra and Luna, and Astra for exceptions, the way Claude's lists Auto, Opus, Sonnet, Haiku and Fable), and a Codex agent works like a Claude one: its chat, Changes card, approvals and questions, Hub tile and History entry are the same. Codex agents read the project's `CLAUDE.md` and your global `~/.claude/CLAUDE.md`. An agent stays on its provider, since its conversation lives there. When a provider's usage limit is reached, new agents start on the other one (a line under the message box says so), while agents already on it wait: their tile turns violet and counts down, a banner over their chat counts down to the second, and they continue by themselves when the limit resets. With both on, the health bar at the top has one part per provider, each with its own level, reset time and week, and the usage card and tab show both. Quick tasks (titles, Auto's ratings, follow-ups, group notes, finding the game folder) run on the provider and model Settings → Providers → Quick tasks picks (Haiku on Claude by default), and on the other provider while that one is off or at its limit. Settings for a provider that is off are greyed out. With both on, the Connectors dialog has a Claude tab (as before) and a Codex tab with Codex's own connectors (`codex mcp`, in `~/.codex/config.toml`), the apps your ChatGPT account gives Codex, and every connector Claude has that Codex does not yet (found by its address, from claude.ai and your own), so setting them up is one click: Connect adds it to Codex and signs in. Connect on a Codex connector signs in, + Add custom connector adds one by URL (with an optional environment variable that holds its API key), ✕ removes it.
- **Queued messages.** A message you send while the agent works waits under the chat, in a dashed bubble, and goes out when the task ends; with several, one goes out per task, in order. Until then you can **Edit** it (it goes back into the message box), remove it (×), or **Send now**, which hands it to Claude Code right away so it reads it in the middle of the task. After you stop a task yourself, the queue waits for you: send the next message, or click Send now.
- **Two agents, one file.** When an agent edits or writes a file that another working agent has edited or written in its current task, both chats get a warning that names the other agent, and both tiles say "⚠ Same file" (point at it for the agent and the files). The warning goes away when one of the tasks ends.
- **Stopping a task.** A working agent's tile shows a ■ next to the × when you point at it, and its message box shows a Stop button next to Send. Both stop the current task (like Stop in the top bar); the agent stays, ready for your next message.
- **Removing a group.** Point at a group's panel in the Hub and click **× Remove group** to remove all its agents at once: the tiles drop out one after another and the panel folds shut. Busy agents are stopped after one confirmation. Their sessions stay in History, and the Category itself is kept.
- **Newest message on the tile.** When you send an agent another message, its tile in the Hub shows that message instead of the first one: as you wrote it at first, then as a short summary. Hover the tile title for the full message and the original task. The agent's title in History stays the first task.
- **Skills.** When the agent runs a skill, or your message starts with `/skill-name`, a row above the answer names the skills it used. The skill's own instructions are not shown in the chat.
- **Full file and side by side.** An opened file (in the file list, or a type's diff from the class diagram) has **Changes | Full file | Side by side** over it. Changes is the diff, where you can comment on lines. Full file is the whole file as it is now, with the added lines in green and the removed ones in red where they were. Side by side shows the file before the task on the left and after it on the right, row by row, the removed and added lines facing each other; the card widens to most of the window while a file is open this way, and long lines wrap. Both versions come from the task's history, not from the file as it is now: a new or deleted file is in the diff whole, and for an edited file the diff is applied backwards (to get the version before) or forwards (when you undid or reverted the change since, to get the agent's version). When the files were reverted across several tasks of a session, the file's changes in the earlier tasks are replayed first. Whitespace differences (tabs shown as spaces in Claude Code's edit reports) do not count. They are not available when the file was changed again since in the same lines. The view you pick last is the one the next file opens in.
- **Code review.** In the Changes card, code files (`.cs`, shaders, scripts) come first; every file starts collapsed, and clicking it opens its diff with line numbers and syntax colors. In each part, modified files come first, then added ones, then deleted ones. Every file that is not code (Unity assets such as `.prefab`, `.asset` and scenes, and also text files, images and other files) is grouped under "Asset changes"; ⤢ in its title opens them in the whole window, with the list on the left and the picked one large on the right (↑ ↓ to go through them, Esc to close). Click any line of a diff (in the file list, or in a type's diff from the class diagram) to comment on it (Ctrl+↩ saves, Esc cancels). **Send N comments** in the card's title puts all comments into the message box as one message, with the file, line and code of each, so you can add to it before you press ↩.
- **Class diagram of C# changes.** The Changes card is one container for a task's changes. When the task changed C# types, it starts on a UML class diagram, with the whole card widened to most of the window; **Diagram | Files** in its title switches to the list of files and back. While the C# is read (about a second, longer the first time in a big project) the card says so; without C# types it shows the files. The diagram shows only the types the task added, changed or removed, each as a box with its name and a stripe in the color of the change (green new, amber changed, red deleted; interfaces in italics). Arrows are curves and show how the types depend on each other (solid with a hollow triangle: inherits; dashed with a triangle: implements; dotted: uses; amber: a dependency that is new in this task), and the lower levels stand on top: a type stands below the types it uses (its arrows point up), and rows too wide for the chat wrap. Types are grouped in a box per namespace, and the namespaces stand under each other, a namespace below the ones it uses. Inside a namespace, each folder has a lane of its own (a faint strip, the same in every row) with its name at the top, so the types of one folder stand together. The canvas is as tall as the diagram, so all of it shows and the chat scrolls past it. Two roles get their own look. A **SystemComposer** (it creates and wires the types of its feature) is a dashed bar down the left side of its namespace, with its name running up along it (the bar, its namespace and the canvas grow to fit a long name); its wiring arrows show only while you point at it. A **Facade** (a type ending in Facade, and its I…Facade interface) is the API other domains use: it has an accent outline and an **API** tag, the interface stands on a row of its own at the bottom of its namespace (where the other domains come in), and arrows into it from other namespaces are drawn thicker. Any other interface that two or more types of other namespaces depend on (a seam that funnels dependencies) also stands on that bottom row. Code from a Unity package (a file under `Packages/com.company.name/` or in the package cache) is drawn apart from the project's own: its container is blue and dashed, with the package's name in a tag on its top edge, and its folders are named from inside the package (`Runtime`, `Editor`). When a container mixes the project's code with a package's, the package's folder gets that look as a card of its own (a package's types and the project's never share a card), and the legend adds **From a package**. Types with the same name in different namespaces are told apart by namespace and `using` lines; two parts of one type (a partial class) are one box. Point at a box for its changed members and to light up its arrows; arrows of a type that uses more than 5 others (a composer, a facade) stay faint until then. Boxes stand well apart, and a box with many arrows is taller, so the arrow ends spread out. **Click a box** and it grows into a panel with that type's diff, at its first change: the panel pops up over the chat, as tall as the code needs (up to the whole chat area), with the chat dimmed behind it. ‹ › or ← → step to the previous or next type, click a line to comment on it, and **Back**, Esc or a click beside the panel shrinks it back into its box. Drag to move, Ctrl+wheel or − + to zoom, Fit to see it all, ⤢ for the whole window (where the wheel zooms by itself). **Find a class** left of those buttons searches the diagram's types by name: as you type, the matching types show in a list under it (names that start with what you typed first, then names that contain it, then names whose capitals spell it, so `pvc` finds `PlayerViewController`). ↑ ↓ choose one, and Tab or Enter fills in its name and moves the diagram so that box is in the middle, outlined for a moment; a type in a collapsed namespace or folder opens that box first. Esc empties the search box. In the whole-window diagram, Ctrl+F (⌘F on macOS) goes to the search box instead of the search of past agents. The whole-window diagram also has a **Review peer**: an agent that reviews the change with you. Until you ask it something, it is only a box at the bottom right of the diagram, with three suggested questions above it (a click or Alt+1–3 asks one). The first question opens the conversation as a panel beside the diagram; × hides the panel again (back to the box), the **Review peer** button in the title bar (there once you asked something) shows or hides it, and New empties the conversation. Your first question goes with the diff of the card's files, and the agent can read and search the project (Read, Grep and Glob only, so it cannot change files or run commands). It runs on Opus, saves no session (so it is not in History), and shows the files it reads and searches above its answer. ↩ asks (⇧↩ for a new line), and Stop ends the answer. The conversation stays with the card when you close the diagram and open it again; its process stops 10 minutes after you close the diagram, and a question after that starts a new one that gets the earlier questions and answers too. The agent's code is in `src/reviewpeer.js`. The diagram also shows the code as the agent left it, rebuilt from the task's history the same way, so undoing or reverting the files later does not change it. The C# is read by `src/csharp.js`, without a compiler: it takes a few milliseconds, but it can miss unusual code. An index of the project's own types (not the package cache) is built in the background, the first time and every 5 minutes, only to tell apart types that share a name; the diagram never waits for it.
- **Undo last prompt.** In an agent's chat, the message box has **↶ Undo last prompt** next to Send when the agent's last task changed files (and it is not working). It puts every one of those files back the way it was before that task: a new file is removed, a deleted file comes back, and an edited file gets its old lines back, newest change first. It applies the task's diff backwards, so it works in git repositories, SVN checkouts and plain folders alike, and it touches only the files, never git's index or your stash. If a file was changed again since in the same lines, it is left alone and the chat says why; changes elsewhere in a file stay. The undone files are crossed out in the task's Changes card, a note in the chat lists them, and your next message tells the agent which files are back as they were. The button then says **↷ Redo last prompt**, which puts the agent's version back. This covers assets too: prefabs, scenes, materials, animations, `.meta` files and other files Unity saves as text, and binary files the task's snapshot recorded, which come back from that snapshot. A moved file goes back to its old folder.
- **What counts as a change.** The card lists only files inside the agent's folder that still exist when the task is done. (That check runs when a task ends; a saved session opened later keeps every file the agent changed, also the ones you reverted since.) Helper scripts the agent writes in /tmp or a scratch folder, and files it creates and deletes again during the task, are left out. A file that existed before and was deleted shows as Deleted.
- **Edit a message and go back.** Point at one of your messages in a chat (also in a saved session from History) and click **Edit** in the margin next to it. Change the text and press ↩ (or Send): the conversation continues from just before that message, with the new text, and that message's answer and everything after it leave the chat. Claude Code resumes the session up to the answer before your message as a new session (`--resume-session-at` with `--fork-session`), so the old conversation stays in History. A running agent restarts in its own tile (a working one asks first, since it stops its task); a saved session starts an agent. When the tasks that leave the chat changed files, a checkbox offers to undo those changes too (newest first, the same as Undo in the Changes card). Editing your first message starts the conversation over.
- **Which message the output answers.** When your message has scrolled out of view, a card in the margin to the left of the chat shows it ("You asked …"), so it never covers the chat. In a window too narrow for that margin, it is a bar at the top of the chat instead. It follows your scrolling: in an earlier answer it shows the message of that answer. It hides while the message itself is on screen. Click it to scroll back to the message.
- **Moving through a chat.** Two buttons at the bottom right of the chat go to your previous (▲) and next (▼) message, so one click skips a long answer; point at one to see which message it goes to (3 of 7); Page Up and Page Down press them, also while you type. Once you have scrolled up, a third button under them goes back to the bottom. They appear only when the chat is longer than the window. Leaving a chat you had scrolled up in (for the Hub, another agent, History) remembers where you were: opening it again shows the same spot, not the end. A chat you left at the bottom opens at the bottom, and an agent that finished while you were away still opens at the start of its answer.
- **Text boxes as cards.** When an agent writes a box drawn with `╔ ═ ╗ ║ ╠ ╣ ╚ ╝` characters (for example from a skill that asks for a CHANGES summary), the chat shows it as a card: the first line in capitals is the title, `╠═╣` lines separate sections, lines in capitals (BEFORE, AFTER) are labels, `•` lines are a list (file names in the code font), lines with `──►` arrows are a chain of steps with the line below as a note per step, and `✓`/`✗` color a step green or red. The Text button shows the box as written. If a box cannot be read, it stays as text. Lines like `+ File.cs (new)`, `~ File.cs` and `- File.cs (removed)` become a list of changes with a green, amber or red sign; lines indented under one are its notes. When a box shares a code block with other text, the rest of the block stays a code block.
- **Text diagrams.** Diagrams an agent draws with line characters (`│ ├ └ ▼ ──`), like a flow of calls or a file tree, get a diagram block: a font where the lines meet, lines dimmed, arrows in the accent color, calls and strings highlighted, and text that gets smaller (down to a readable size) instead of a scroll bar. Point at it for **Copy**. Other code blocks in answers wrap long lines instead of scrolling sideways.
- **Answers about behaviour, not files.** Agents are also told (through `--append-system-prompt`) that the Changes card under their answer already shows every changed file, its diff and the class diagram. So their final message leaves out lists or boxes of changed files and before/after diagrams of classes and calls, and talks about what behaves differently: for the player or user, what stays the same, how to test it, what they could not check, and open questions. When a project's CLAUDE.md or a skill asks for a CHANGES box or a visual summary of the code, agents keep the visual part for the behaviour instead.
- **Images and videos.** Agents are told (through `--append-system-prompt`) that they can show an image or a video in the chat with a Markdown image and a file path, for example `![Grass texture](Assets/Textures/Grass.png)`; videos (mp4, webm, mov) become players. After each task, a **Media** card lists the images and videos in the agent's folder that were created or changed during the task, also when the agent did not mention them (found by modification time; Unity's Library, Temp and Logs are skipped). Click an image to see it at full size. Unity formats Chromium cannot show (tga, psd, exr, tif) are converted to a PNG preview with macOS's `sips`.
- **How changes are found.** In a git repository, the app saves a snapshot of the working tree before each message (`git stash create`, which does not change your files or your stash list) and compares the files to it when the turn ends. That way it also catches changes made by shell commands, and it leaves out changes that existed before the turn. Outside git (for example in an SVN checkout), the app keeps its own git repository for that folder in its settings folder (`snapshots/`) and records code files and assets stored as text there (prefabs, scenes, `.asset`, materials, animations, `.meta`, JSON and the like; not textures, models or sounds, which can be gigabytes); it never writes into your folder. The first time that takes a while in a big project, so the app records the folders of the agents on the Hub in the background a few seconds after it starts. Embedded packages that are git repositories get their own git snapshot. Changes to other files outside git come from the reports that Claude Code's Edit and Write tools send. The comparison also finds what you or other agents changed in the same folder meanwhile, so a task's card keeps only the files the agent changed: the ones it edited or wrote with its tools, named in a command or script that writes (`sed -i`, `cat >`, a Python script in a heredoc), or matched with a wildcard path in one (a script that edits every file of `glob('Expedition/**/*.cs')`, or renames `Sprint/SprintCycle*`; the path needs a folder name, so `**/*.cs` alone does not count). Deleted or moved files also count when the command named their folder.
- **Parallel agents.** Every agent is its own `claude` process. The Running list shows each agent's state: working (amber), waiting for you (green), or error (red). You get a notification when an agent finishes, asks a question or needs approval while the window is in the background; click it to open that agent. The badge on the Dock icon (on Windows, on the taskbar button) counts the agents that need you: those waiting for your answer or approval (until you reply) plus the finished ones you have not opened yet (until you open them), and the taskbar button flashes when one more starts waiting.

## Multi-agent pipeline

Settings → **Multi-agent** sets up a pipeline of agents for implementing tasks, for example understand the requirements → make a plan → implement → review. It is **off by default**: the main switch at the top turns all of it on or off.

While it is on, a **⛓ Pipeline** button sits under the message box in the Hub. With it lit, the new agent is a *governor*. It does not do the work itself. It hands each step to that step's own agent (a Claude Code sub-agent), recaps what came back as a `Milestone:` line (shown in the chat's Progress panel), fixes gaps and contradictions between steps, and passes everything each step needs on to the next one. It is still one agent, one chat and one session in History; resuming it later keeps it a pipeline. Claude only: the button is greyed out while the next agent would start on Codex.

The editor:

- **The graph.** *Your task* is on the left, *Done* is on the right, and the agent cards sit between them. Drag a card by its title to move it. Drag from the dot on its right side to another card to connect them, and click a line to remove it. **+ Agent…** adds a card, and × removes one. On each card you pick its agent type, how many agents run the step at the same time (×2 means two at once, each with its own part or angle, merged by the governor), and an optional note for that step. Steps that do not depend on each other run at the same time.
- **The reviewer box** around the cards reviews the whole result when the graph is through. When the reviewer finds blocking problems it goes back to the step you pick (by default the Implementer) and round again, up to the number of rounds you set. Untick it to run without a review loop.
- **Warnings** under the graph, and a ! on the card concerned: a card with no input, an output that goes nowhere, a card that is not reached from Your task or does not lead to Done, nothing connected to Done, a circle of connections (go round with the reviewer box instead), a missing agent type, or a review loop without a step to go back to. Click a warning to show its card. You can save with warnings, and the governor works around them.
- **Agent types**: the app comes with a Requirements analyst, a Planner, an Implementer, a Tester and a Code reviewer. Each has a description, a model (the same as the agent's, or Opus, Sonnet or Haiku), its tools (all, read only, or read + shell) and its instructions. You can change the built-in ones (*Restore its instructions* puts them back) and add your own with **+ New agent type**. **Reset to the default pipeline** puts back the graph and the types.

The setting is `multiAgent` in config.json: `{ enabled, types, nodes, edges, loop }`.

## Settings

Click **Settings** in the Hub (or at the bottom of History) to open the Settings screen: every setting below as a form, in four parts (New agents, The app, Stuck agents, Claude Code). **Save** (or Ctrl+↩) writes them to `config.json` and they apply right away; Esc or Cancel leaves them as they were. **Open config.json** at the bottom opens the file itself, for settings the screen does not show; after editing the file by hand, restart the app.


**Account** (the first part of Settings) shows the Claude account that Claude Code, and so every Claude agent, uses: its email, organization and plan. Below it are the other accounts you signed in with before. **Switch** puts that account's saved login in place of the current one, so you don't sign in again; the health bar then shows that account's limits. When agents are working, the app asks first, because they may finish their task on the new account. **Add another account…** signs Claude Code in with a new account in your browser (if the page signs you in with the current account, sign out of claude.ai there first). The account you were on stays in the list. **×** removes an account and its saved login. When a saved login has expired, its button says **Sign in…** instead of Switch.

How switching works: Claude Code keeps its login in the macOS keychain (the item `Claude Code-credentials`; on Windows and Linux, `~/.claude/.credentials.json`) and the account's details in `oauthAccount` in `~/.claude.json`. Each time Settings opens, and before every sign-in, the app saves the current account's login: on macOS in the keychain (one `Agent Hub Claude account` item per account), on Windows and Linux in `claude-accounts.json` in the app's data folder, which only you can read. Switching writes the other account's login and details back into Claude Code's places. The logins of your connectors (`mcpOAuth`) stay as they are. With `CLAUDE_CONFIG_DIR` set (in `env`), the app uses that folder, as Claude Code does.
- `claudeEnabled`, `codexEnabled`: which providers agents can run on (Claude on, Codex off by default). `defaultProvider`: `claude` or `codex`, the one new agents start on.
- `helperProvider`: `claude` or `codex`, where quick tasks run; `claudeHelperModel` (default `haiku`) and `codexHelperModel` (default `luna`, Codex's Haiku: its newest Luna, run at medium effort, which matched Haiku's ratings) are their models.
- `codexExtraArgs`: extra flags for every Codex agent's `codex app-server`. `env` applies to agents on both providers.
- `codexPath`: path to the `codex` binary; empty means Homebrew, npm or `~/.local/bin`. `codexModel`: `auto` (the default: Luna, Terra or Sol for each task, picked like Claude's Auto picks Haiku, Sonnet or Opus), a family (`sol`, `terra`, `luna`, `astra`: its newest model), or a model id. `codexEffort`: `low`, `medium`, `high`, `xhigh`, `max` or `ultra`; empty for Auto (with the Auto model) or the model's default. `codexFastMode`: `true` to start Codex agents on Codex's Fast tier (1.5 to 2 times faster; for Sol and Astra it uses your limits faster); the ⚡ in the model menu changes it per agent.
- `claudePath`: path to the `claude` binary. When it is empty, the app finds every Claude Code installation (Homebrew, `~/.local/bin`, and the copy inside the Claude desktop app) and uses the newest one. A newer Claude Code knows about newer models.
- `defaultPermissionMode`: `bypassPermissions` (the default), `auto`, `acceptEdits`, `default` or `plan`. You can change the mode of a running agent with the menu under the message box.
- `defaultModel`: a model value from the model menu. The default is `opus`, which always means the latest Opus (Opus 5.5 today).
- `defaultEffort`: `low`, `medium` (the default), `high`, `xhigh` or `max`. Empty means the model's own default.
- `defaultFastMode`: `true` to turn fast mode on for new agents.
- `defaultFolder`: the folder for a new agent when you have not started one in Agent Hub yet.
- `extraArgs`: extra flags for every agent, for example `["--add-dir", "/some/path"]`.
- `env`: extra environment variables for every agent.
- `stuckAfterSeconds`: an agent shows as **Stuck** (amber ⏳ on its tile, with a notification) only when it has been waiting this long (default 30) for Unity to be ready: the Unity tools that wait for the editor (`unity_wait_for_ready`, `unity_status`, `unity_recompile`, refresh), one call or several in a row. Other tool calls never make it stuck, however long they run or however often they repeat. It is working again as soon as it does something else.
- `notifyWhenDone`: show a notification when an agent finishes or needs you.
- `sounds`: sound feedback for everything you do and everything the agents do. Agents: a start sound (and a bubbling one when its message lands in its tile in the Hub), a question or an approval, finishing, an error (not when you stop it), and looking stuck. You: sending a message to an agent, opening an agent or a saved session and going back to the Hub, stopping a task, allowing or denying a tool and answering a question, adding or removing an image or video in the message box, removing an agent or a group, dragging tiles, and small clicks for menus, cards, dialogs and options. Notifications are silent while this is on. Reopen the app after changing it.
- `hubAfterSend`: open the Hub after you send a message (default `true`).
- `summarizeTitles`: name new agents with a short summary of your message (default `true`).
